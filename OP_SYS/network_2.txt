Pakett, marsruut ja privaataadress

kapseldamine - andmed pakitatakse kihtidega
marsruudi valik - voidab koige pikem sobiv prefix, tabeli kuvatud ridade jarjekord ei otsusta
privaataadress - sisevorgus marsruuditav - seda voivad kasutada nii kliendid kui ka serverid

NAT taastab vastuse sihtaadressi. Marsruut määrab tee selle sihini.
Privaatne aadress ega NAT üksi ei määra tulemüüri lubasid.

ICMP ja paketitee kontroll
ping - ICMP Echo Request / Reply: päring ja vastukaja
traceroute - Erineva TTL-iga proovid; hüpetest võivad tulla ICMP Time Exceeded vastused. (naitab kui palju ruutereid pakett labib)
ICMP veateade - Näiteks sihtkoha kättesaamatus.

traceroute -n 198.51.100.20

Laborimudeli käsud. Ruuter vähendab IPv4 TTL-i; nulli jõudnud paketti edasi ei saadeta.
Ping-vastus ei tõenda veebiteenuse töötamist.

UDP ja TCP teenus rakendusele

UDP {
    andmeyhik eraldi - datagrammid
    yhenduse loomine -tcp kaepigistust ple
    kadu ja jarjekord - pole garanteeritud
  }

TCP {
    Jarjestatud baidi voog
    yhenduse loomine enne tavalist andmevahetust
    Järjestamine, kinnitused ja kordussaatmine
  }

UDP säilitab datagrammi piiri; TCP sõnumipiiri määrab rakendus.
TCP ei taga lõputut edu: ühendus võib ka veaga katkeda.


TCP ühenduse loomine
Klient C: 192.168.11.66; server S: 198.51.100.20:80. Otspunktide skeem, NAT-i näitamata.

1. SYN: yhenduse algatamine
2. SYN + ACK: serveri vastus
3. ACK: Kliendi kinnitus

Mõlemal poolel tekib selle ühenduse TCP olek.

Käepigistus kooskõlastab ühenduse; see ei krüpteeri andmeid.


TCP baidivoog ja rakenduse sõnumid

Näide: kaks edukat send()-kutset annavad kokku 600 baiti. Üks võimalik vastuvõtt:

Saatmine - send: 300 baiti | send: 300 baiti
Baidivoog - 600 baiti samas järjekorras
Vastuvõtt - recv: 200 | recv: 400

• Ühe recv() tagastus ei pea vastama ühele send()-kutsele.
• Rakendus määrab sõnumipiiri: näiteks pikkuseväli või eraldaja.
Loe tagastatud baitide arvu ning kogu vajadusel sõnum osadest.


Järjenumber, ACK ja kordussaatmine

Loodud ühenduse andmevoog: SEQ on esimese baidi number; ACK on järgmine järjest
oodatud bait.

1 SEQ=1000, 500 baiti: 1000--1499 jõuavad kohale | ACK=1500
2 SEQ=1500, 500 baiti kaovad teel | Uusi baite pole kinnitada
3 Taimer aegub; saatja kordab baite 1500--1999. Kohale jõudes ACK=2000

ACK kinnitab kõik sellele eelnevad baidid selles voos.
ACK kinnitab TCP vastuvõttu, mitte rakenduse tehtud tööd.

Sokkel, deskriptor ja otspunkt

Protsess fd=7 --(kohalik viit)->OS-i sokliobjekt olek ja phvrid--(TCP yhendus)->Vastaspoole otspunkt 198.51.100.20:80

• Sokkel: OS-i hallatav suhtluse otspunkt.
• Failideskriptor: protsessi tabelis olev täisarvuline viit.
• IP ja port: võrgu otspunkti aadress TCP kontekstis.
Näites on deskriptor 7 juba eraldatud; selle number ei määra TCP porti.
Rakendus annab süsteemikutsele FD; tuum leiab selle kaudu sokli.


Kliendi ja serveri süsteemikutsed

Server: kohalik port 80
lfd = socket(...);
bind(lfd, ...);
listen(lfd, 16);
cfd = accept(lfd, ...);
recv(cfd, ...);
send(cfd, ...);
close(cfd);

Klient: ühendus serveriga
fd = socket(...);
connect(fd, ...);
send(fd, ...);
close(fd);

Kliendi kohaliku aadressi ja ajutise pordi võib valida OS.
accept() annab ühendusele uue FD; kuulav sokkel jääb alles.


Üks kuulav port, mitu ühendust

Serveri vaade: R1 PAT-i taga on kaks klienti, välispordid 62001 ja 62002.


FD | Sokli roll |Kohalik Port | Vastaspoole port
7 - Kuulav - 198.51.100.20:80 - Kindel vastaspool puudub
8 - Ühendus A - 198.51.100.20:80 - 203.0.113.2:62001
9 - Ühendus B - 198.51.100.20:80 - 203.0.113.2:62002

• TCP ühenduse eristab aadresside nelik: mõlema poole IP ja port.
• Üks protsess võib hallata mitut ühendatud soklit.
Port 80 võib olla ühine; vastaspoole aadressipaar eristab ühendusi.


Saatmis- ja vastuvõtupuhvrid
                                                        <-(TCP ACK)--
kliendi rakendus --(send())-> kliendi tuumsaatmispuhver --(TCP ja paketitee)-> Serveri tuum ja vastuvotmisbuffer --(recv())-> Serverirakendus

• send() tagastab kohaliku saatmise jaoks vastu võetud baitide arvu.
• TCP ACK kinnitab vastaspoole TCP vastuvõttu, mitte rakenduse tööd.
• recv() toob olemasolevad voobaidid rakenduse puhvrisse.
Saatmiskutse edu ei tõenda, et serveri rakendus andmed juba töötles.


Blokeerumine ja äratamine
n = recv(fd, buf, 4096, 0); // TCP, blokeeriv sokkel

• Kui andmeid veel pole ja voog jätkub, võib lõim jääda ootama.
• Andmete saabumine võib muuta lõime käivitatavaks.
• Ajastaja annab CPU aja; kutse saab jätkata ja tagastada.

n > 0 - nii mitu baiti on kopeeritud buffrisse
n == 0 - EOF: vastaspool lõpetas saatmise, varasemad baidid on loetud.
n == -1 - Viga või katkestus; täpsem põhjus on errno-s.


Soklite vaatamine käsuga ss

Serveri lühendatud näidisväljund; protsessiinfo ja järjekorraveerud on siin välja jäetud.

$ ss -ltn
State  Local Address:Port  Peer Address:Port
LISTEN 198.51.100.20:80    0.0.0.0:*
$ ss -tnp
ESTAB 198.51.100.20:80 203.0.113.2:62001
ESTAB 198.51.100.20:80 203.0.113.2:62002

• -l: kuulavad; -t: TCP; -n: numbrilised aadressid ja pordid.
• -p: seotud protsessid, kui õigused lubavad nende infot näha.
• LISTEN: ootab ühendusi. ESTAB: TCP ühendus on loodud.

ESTAB ei kinnita veel HTTP päringu edukat täitmist.
